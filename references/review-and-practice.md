# Conversation review and practice

Read this reference for a multi-message review, recurring pattern diagnosis, post-date chat review, or deliberate practice.

## Review a real conversation

### Build a short timeline

Segment the transcript by meaningful changes rather than every message:

- opening and initial premise;
- moments of mutual engagement;
- topic deepening or emotional disclosure;
- invitations, ambiguity, refusals, or boundaries;
- repair attempts and endings;
- later outcomes, if known.

Mark only observable turning points. Do not invent causality from sequence alone.

### Identify the interaction loop

For each important loop, describe:

```text
Trigger -> user's move -> other person's response -> short-term effect -> likely repeated cost
```

Examples of patterns to test, not assume: interview-style questioning, over-explaining, escalating before reciprocity, withdrawing as punishment, missing invitations to deepen, avoiding clear asks, or carrying the entire conversation.

### Evaluate the user's choices

Use qualitative ratings (**strong / mixed / weak / not enough evidence**) instead of fake precision unless the user explicitly asks for a score.

- **Reading accuracy** — distinguished text from inference and noticed contrary signals.
- **Context fit** — matched the relationship stage, medium, and current mood.
- **Emotional attunement** — responded to the person's experience without performing therapy.
- **Self-expression** — contributed a real view, preference, story, or boundary.
- **Reciprocity** — neither interrogated nor did all the conversational labor.
- **Pressure calibration** — intensity, intimacy, and requests fit the evidence.
- **Conversational affordance** — made the next response easy without demanding it.
- **Authenticity** — sounded plausible for the user rather than like a coach or persona.

For each material weakness, cite a specific fragment, explain its effect, and propose one behavior change. Do not grade personality.

### Separate quality from result

Review two questions independently:

1. Was the user's message clear, respectful, stage-appropriate, and authentic?
2. What did the other person's response reveal about mutual interest or fit?

A good message may receive no reply. A manipulative message may receive a reply but still be poor relationship practice. Do not reward only conversion.

### Produce an improvement experiment

End with one small experiment for the next comparable interaction. It must be observable, such as:

- ask one fewer follow-up and add one personal contribution;
- turn a vague invitation into one concrete option with an easy decline;
- stop after one unanswered follow-up and watch whether initiative becomes reciprocal;
- acknowledge emotion before solving;
- replace an implied test with a direct, low-pressure question.

State what result would support or falsify the hypothesis. Do not change several variables at once.

## Full review output

```text
眼前结论：用户现在最该知道的一件事
阶段变化：从哪里到哪里，证据与置信度
有效片段：具体片段 -> 为什么有效
摩擦点：具体片段 -> 可能影响 -> 另一种做法
互动循环：Trigger -> move -> response -> effect
对方反馈说明了什么：事实 / 推测 / 未知
下一次实验：一个行为变化 + 观察指标
```

## Practice mode

Use practice mode only when the user asks to train, simulate, or draft first.

1. Choose one narrow skill: opening, building depth, playful response, invitation, handling ambiguity, repair, boundary, or graceful close.
2. Give a realistic scenario with relationship stage, the other person's last message, and the user's goal.
3. Wait for the user's draft. Do not reveal a model answer first.
4. Evaluate the draft with the review dimensions most relevant to that scenario.
5. Preserve what worked, identify the single highest-leverage change, and ask the user for one revision.
6. After revision, compare the two versions by effect, not by cleverness. End with one transferable principle.

If the user asks to see examples immediately, show structures rather than a memorized line library:

```text
acknowledge the detail -> add a genuine reaction -> offer one optional continuation
shared context -> small specific invitation -> easy decline or alternative
name the ambiguity calmly -> ask one concrete question -> stop explaining
```

## Privacy and memory

Do not create a persistent dossier by default. If the user explicitly asks to track progress, store only a de-identified summary of stage evidence, recurring user habits, experiments, and outcomes. Never store screenshots, handles, phone numbers, addresses, workplace details, or intimate content unless the user explicitly requests that exact retention.
